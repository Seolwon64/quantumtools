# 양자 명세 — 회로 모델 · 게이트 · 측정 · QASM

회로 데이터 모델, 게이트 배치, 측정과 궤적, 고전 레지스터, 직렬화와 QASM 변환의
규격. 디자인 재작성과 무관하게 유효한 계약과 회귀 교훈을 담는다. 함수 시그니처와
내부 동작은 소스가 정의처이므로 여기 적지 않는다.

## 1. 큐비트와 상태

- 전역 상태는 2ⁿ차원 복소 상태벡터다. 큐비트 수와 열 수에 상한이 있다 — `circuit.js` 의
  `MAX_QUBITS = 6`, `MAX_COLUMNS = 12`. 저장값은 큐비트 수가 범위 밖이면 통째로 버리고, 저장값·
  공유 URL 모두 열은 상한까지만 읽는다(`createCircuitController` 초기화).
- **화면 판단의 최악은 6큐비트다.** 상태벡터 64항, 확률 64기저(6큐비트부터는 상위 32개만 두고
  나머지는 Show all 뒤로 — `computeVisibleProbabilities`), Q-sphere 64개 노드·라벨. 게이트 행렬
  표시는 최대 8×8(3큐비트 게이트)이고 RC3X(4큐비트, 16×16)는 그리지 않는다. 축소 밀도행렬은
  큐비트 수와 무관하게 늘 2×2 다. **8큐비트를 전제로 크기를 판단한 적이 한 번 있었다** — 화면
  폭·높이를 정할 때는 이 상한에서 출발한다.
- Bloch sphere는 **선택된 큐비트 1개의 축약 밀도행렬**에서 벡터를 구한다. 얽히면 벡터
  길이가 1보다 작아져 구 안쪽으로 들어가는 것이 정상 동작이다.
- 재생 단위는 칼럼이다. 한 스텝 = 그 칼럼의 모든 게이트를 동시 적용.

## 2. 비트 순서(endianness) — 바뀌지 않는 계약

상태벡터·확률 표기는 **little-endian(q0이 오른쪽 끝, Qiskit 관례)** 이다. 공유 URL과 QASM
호환이 여기 걸려 있으므로 재작성해도 바뀌지 않는다.

화면에 `|q(n-1) … q1 q0⟩` 라벨을 상시 표시해 규약을 드러낸다. 확률 패널이 고전
비트를 보여줄 때는 `|c1 c0⟩`로 바뀌어 **라벨이 모드를 항상 드러낸다** — 이 라벨
덕분에 "패널 의미가 회로마다 바뀐다"는 문제가 사라진다.

## 3. 회로 데이터 모델

- **정규(canonical) 셀:** 게이트 이름 + `targets` + `controls` + `params`. 모든 게이트가 임의
  개수의 컨트롤을 가질 수 있다. CNOT·CCX·CZ·CSWAP은 별도 종류가 아니라 base 게이트 +
  컨트롤이다. 셀은 **홈 행 하나에만** 저장하고 나머지 관여 큐비트는 필드로
  기록한다.
- **상대위상 게이트(RCCX/RC3X)는 컨트롤 경로를 타지 않는다.** 관여 큐비트를 전부
  `targets`에 담고 타깃을 마지막에 둔다. 정확한 CCX/C3X가 **아니므로** 일반 컨트롤로
  표현하면 안 된다. 엔진은 분해로 상대위상 유니터리를 적용하며 행렬을
  하드코딩하지 않는다.
- **엔진은 컨트롤을 일반적으로 처리한다** — n개 컨트롤 = "모든 control 비트가 1인 기저
  상태 쌍에만 base 게이트 적용". 게이트별 특수 분기가 없다.
- Measure/Reset/Barrier/제어점에는 컨트롤을 붙일 수 없다.
- `targets`/`controls`는 **큐비트 인덱스 전용**이다. 고전 비트는 `params`로.

## 4. 게이트 배치와 컨트롤 부착

- **컨트롤 부착 경로는 둘이지만 변형 지점은 하나다.** 빈 칸에 드롭하는 경로와
  게이트 위에 드롭해 팝오버로 고르는 경로가 **같은 함수 하나만** 거치므로, 같은
  큐비트를 가리키면 **결과 셀이 완전히 동일**하다(테스트가 셀 비교와 직렬화 문자열
  일치로 고정).
- **빈 칸 드롭은 같은 칼럼에서 가장 가까운 게이트에 붙는다.** 이 최근접 규칙은 회귀
  테스트로 고정돼 있다.
- 후보는 드롭한 큐비트가 아니라 **열 전체** 기준이다. 그래서 CZ처럼 두 점이 화면상
  구별되지 않는 게이트도, 대칭인 게이트도 **어느 점에 붙여도 같은 결과**가 나온다
  — 전용 정규화 코드가 필요 없다.
- 후보 검사는 **부작용이 없어야 한다**(회로·undo 스택 불변). 그래야 팝오버를
  취소해도 아무 흔적이 남지 않는다.
- 여러 개를 한 번에 붙여도 **undo는 한 단계**다. 선택 순서와 무관하게 같은 셀이
  나오도록 오름차순 정규화해 덧붙이되 기존 컨트롤은 재정렬하지 않는다 — 직렬화
  출력이 흔들리면 안 되기 때문.
- **게이트 좌클릭은 메뉴를 연다. 게이트를 클릭으로 삭제하는 경로는 없다.** 삭제는 메뉴의
  Delete 또는 선택 상태에서 Delete/Backspace 키다(입력 필드 포커스 중엔 미개입). 예외는
  제어점(•)이다 — 좌클릭은 그 제어 하나만 떼고(게이트는 남는다), 메뉴는 우클릭으로 연다
  (`grid.js` 의 클릭·contextmenu 핸들러).

## 5. 측정 — 두 실행 경로

**경로 선택은 회로가 정한다. 사용자 스위치가 아니다.** 판정 함수 하나가 결정하고
상태 접근·검증·확률 패널·UI 표시가 모두 그 값을 본다.

- **궤적 경로**(중간 붕괴, RESET, 조건부 중 하나라도 있음): 순차 실행하며 측정에서 실제로
  사영·정규화한다. 이후 게이트는 붕괴된 상태 위에서 적용된다.
- **이론 경로**(그 외): 측정은 no-op, 조건부만 양자 제어로 바꾼다. 붕괴가 없거나 붕괴
  뒤에 연산이 없으면 이 값이 **정확**하고 비용이 0이다. RESET 은 이 경로에 들어오지 않는다 —
  엔진(`applyPlacement`)이 거부한다.

**예전 설계의 실패 — 같은 실수를 반복하지 마라.** Inspect 스위치가 꺼져 있으면
`h/measure/h/measure` 같은 회로를 지연 측정으로 계산해 한 결과를 100%로 보여줬다. **그
값은 틀렸다** — 정답은 네 결과 각각 25%다. "정확한 답을 보려면 스위치를 켜라"는
역할 배분 자체가 잘못이었다. 지금 Inspect는 **스텝 컨트롤을 여닫는 것만** 한다. 두
모드가 같은 캐시 궤적을 쓰므로 최종 상태가 일치한다.

**되감기 결정론이 이 설계의 핵심이다.** 매번 새 난수를 뽑으면 스텝 재생이 성립하지
않는다. 시드 하나로 결정론적 수열을 만들어 **같은 스텝이면 항상 같은 상태**가
나오게 한다. **시드는 회로가 바뀌어도 유지한다** — 결과가 달라졌을 때 편집
때문인지 새 난수 때문인지 구분할 수 있어야 하기 때문. 시드를 저장하지는
않는다(새로 열었는데 같은 궤적이면 오히려 혼란스럽다).

**RESET 이 있으면 위치와 무관하게 궤적 경로다.** 리셋은 "측정 + 결과가 1 이면 X" 라 그
자체가 붕괴 뒤의 연산이다. 올바른 리셋은 대상 큐비트에 대해 **주변화**한 뒤 그 큐비트를 `|0⟩` 에
둔다(ρ → |0⟩⟨0| ⊗ Tr_q(ρ)). 대상이 얽혀 있으면 결과는 혼합 상태라 **어떤 상태벡터로도 표현되지
않는다** — 이론 경로는 순수 상태 하나만 다루므로 거기서는 정확히 계산할 방법이 없다. 확률·큐비트별
축소 ρ 는 주변화로 정확히 낼 수 있지만 진폭·Q-sphere 는 낼 수 없어 표시 방식이 바뀐다(§7 범위 밖).

- **예전 실패.** 엔진의 리셋은 `|0⟩` 성분만 남겨 다시 정규화하는 **사후선택**이었고, 판정 함수는
  RESET 을 붕괴로만 세어 "그 뒤에 연산이 없으면" 이론 경로로 보냈다. 그래서 끝에 있는 RESET 이
  조건부 분포를 보였다 — `H q0 · CX q0,q1 · RESET q0` 가 q1 을 100% `|0⟩` 으로 보였다(정답 50/50).
- **사후선택은 엔진에서 지웠다.** 판정만 고치면 `simulate()` 처럼 판정을 거치지 않는 다음 호출자가
  같은 문으로 들어온다. 그래서 `applyPlacement` 가 RESET 을 받으면 예외를 던진다.
- **상태(얽힘)에 따라 경로를 고르지 않는다.** 사후선택이 맞는 경우는 대상이 얽히지 않았을 때뿐인데,
  그때는 궤적의 모든 갈래가 같은 상태로 끝나 평균이 **정확값과 같다**(테스트가 고정). 얽힘 판정은
  렌더마다 시뮬레이션과 임계값을 요구하고, "측정 뒤 같은 큐비트 리셋" 처럼 얽힘과 무관하게 이론
  경로가 다루지 못하는 회로도 남는다. 대가는 라벨이다 — 그런 회로에도 "One trajectory" 가 붙고,
  끝단 측정이 함께 있으면 Classical 막대가 N회 계수가 된다(`docs/backlog.md`).

**판정이 세 번 틀렸다.** (1) **마지막** 붕괴 기준이라 "측정 → H → 측정"을 빠른
경로로 잘못 분류했다 → **첫** 붕괴 기준으로 고쳤다. (2) 조건부 검사가 "붕괴 없음"
조기 반환보다 뒤에 있었다. 기록된 적 없는 비트를 조건으로 쓰면 지연 변환은 값이
아니라 **에러**를 내는데 궤적은 정확히 다룬다 → 조건부 검사를 맨 앞으로 옮겼다.
(3) RESET 을 붕괴로만 셌다 → 위의 규칙으로 RESET 을 조건부 바로 뒤에서 따로 본다.

**Resample은 Inspect가 꺼져 있어도 알린다.** 예전에는 켜져 있을 때만 알렸는데, 꺼진
상태의 Resample이 화면을 바꾸지 않은 채 **시드만 조용히 바꿔 놓고** 나중에 Inspect를
켜는 순간 상태가 튀었다.

## 6. 확률 집계

궤적 한 번 순회로 두 분포를 만든다.

- **Classical**: 각 궤적의 고전 비트를 비트열로 **센다**. 측정 결과는 이산적이다.
- **Qubits**: 각 궤적의 최종 순수 상태에서 확률을 구해 **평균**한다. **궤적마다 기저
  하나를 샘플링해 세지 않는다** — 기대값은 같지만 분산이 훨씬 크다. 이 값은 앙상블
  밀도행렬의 대각 성분과 정확히 일치하고, 측정 없는 회로에서는 이론값과 **정확히**
  같아진다(테스트가 고정).
- 궤적이 필요 없으면 궤적을 돌리지 않는다. 이론 확률을 주변화하면 그게 정확하고
  비용이 0이다.
- **고전 비트 막대에는 진폭도 위상도 없다.** 툴팁에서 그 행을 **뺀다**(0을 넣어 있는
  척하지 않는다). 같은 이유로 스텝 전환 트윈을 Classical 모드에서는 그리지 않는다 —
  축이 다른 두 분포를 보간하는 셈이라 라벨과 막대가 어긋난다.
- 표시 필터는 **DOM 무관 순수 함수**가 계산한다. 샘플링에서 관측된 기저는 어떤
  필터로도 숨기지 않는다.
- **진폭·계수의 표시 형식도 `probmodel.js` 에 있다**(자릿수 고정·`-0` 정규화·조각 분해). 상태벡터
  패널이 계수를 열에 나눠 넣어 소수점을 맞추려면 문자열이 아니라 조각이 필요하고, 밀도행렬과
  같은 포매터를 써야 두 패널의 숫자 모양이 갈라지지 않는다. 게이트 행렬(`gatematrix.js`
  `formatComplex`)과 툴팁은 다른 자릿수를 쓴다 — 통일은 `docs/backlog.md`.
- **숨김 기준은 패널마다 다르다 — 둘을 섞지 않는다.**
  - 상태벡터 "Hide 0.00" 은 **계수**로 거른다 — 표시 자릿수에서 0 으로 찍히는 항만 숨긴다
    (`probmodel.js` `AMP_DISPLAY_EPS`). 확률로 걸렀더니 진폭 0.06 처럼 계수로는 뚜렷한 값이 사라졌다.
  - 확률 "Hide 0%" 는 **확률**로 거른다 — 수치 오차 수준(1e-9) 이하만 숨긴다
    (`quantum.js` `computeVisibleProbabilities`). 이 기준의 재검토는 `docs/backlog.md`.

## 7. 고전 레지스터와 조건부

- 셀 구조는 그대로 두고 `params`만 확장한다 — 측정은 기록 대상 비트, 조건부는 조건
  비트를 담는다. 고전 비트 수는 큐비트 수와 독립이고, 줄일 때 범위 밖 참조를
  정리한다.
- **조건부는 기록된 고전 비트를 그대로 읽는다.** 아직 기록된 적 없는 비트는
  **0(거짓)** 이다 — 고전 레지스터는 0으로 초기화되므로 그게 정확한 의미다.
- 지연 측정 변환은 조건부를 양자 제어로 바꾼다. **열 구조를 바꾸지 않으므로** 스텝
  재생·되감기 의미가 그대로다. 조건이 없으면 원본 그리드를 그대로 반환해 기존
  회로 결과가 비트 단위로 불변이다.
- **변환은 딱 한 번만 적용한다.** 이미 변환된 그리드를 다시 변환하면 제어가
  중복으로 붙어 **잘못된 검증 실패**가 난다.
- **컨트롤러의 어떤 경로도 예외에 의존하지 않는다.** 예상 가능한 실패를 예외로
  만들면 호출부마다 try/catch가 필요해지고 하나라도 빠지면 재생 루프가 죽는다.
  엔진이 던지는 예외도 `stateAt` 이 사유(`error`)로 바꾼다 — 그대로 올리면 `notify` 가 렌더를
  통째로 삼켜 URL 로 연 회로가 백지로 남았다(로드 시 `onChange` 0회). `validate` 도 같은 판정을
  써서 그 회로의 재생을 막는다. 궤적 분기는 아직 감싸지 않았다(`docs/backlog.md`).
- **[정직성] 궤적으로 계산되는 회로에는 라벨을 붙인다.** 축소 밀도행렬 영역에도
  **같은 라벨이 필요하다** — 궤적 하나는 순수 상태라 Purity가 늘 1로 나오는데 실제
  앙상블은 혼합 상태다. 라벨이 없으면 "측정했는데도 순수하다"는 잘못된 결론으로
  이어진다.
- **범위 밖:** 복합 조건, 밀도행렬 기반 혼합 상태. (측정 후 큐비트 재사용은 한때 범위 밖이었다 —
  지연 변환이 그런 회로를 거부했기 때문이다. 지금은 궤적 경로가 실제 붕괴로 정확히 다룬다:
  `circuit.js` `validate` 가 궤적이 필요한 회로를 먼저 통과시킨다.)

## 8. 게이트 행렬 표시

- **행렬을 유도하지 않는다.** 기저 벡터를 엔진에 통과시켜 열을 하나씩 얻는다 →
  SWAP·RXX·RCCX처럼 "행렬이 코드에 없는" 게이트도 자동으로 정확하고 분해를 두 번 적을
  일이 없다. **엔진·회로는 절대 수정하지 않는다.**
- **로컬 비트 순서 = 실제 큐비트 번호 오름차순.** 역할 순으로 고정하면 RCCX(a,b)와
  RCCX(b,a)가 같은 행렬이 되어 두 배치의 차이가 사라진다.
- **분해 정의는 데이터 한 곳에서 온다.** 엔진도 그걸 순회하므로 시뮬레이션과 표시가
  어긋날 수 없다.

## 9. 직렬화 · 공유 URL · 하위 호환

- 회로를 JSON→base64url로 인코딩해 URL 해시로 공유한다. 페이지 로드 시 해시가
  저장값보다 우선하고, 편집이 오래된 해시로 되돌아가지 않도록 즉시 제거한다.
- **기존 공유 링크를 깨뜨리지 않는 것이 계약이다.**
  - 구버전 셀은 마이그레이션 함수가 정규형으로 변환한다. 저장값 로드와 URL 디코드
    양쪽에서 자동 적용되고, 배포된 구버전 URL은 전용 분기로 계속 열린다.
  - **RCCX/RC3X는 구버전에서도 게이트 이름이 보존되므로** 마이그레이션이 정확히
    복원한다 — 예전에는 CCX로 흡수돼 다른 회로가 됐다.
  - 새 필드가 없는 기존 URL은 기본값으로 열리고, 기본값과 같으면 필드를 넣지 않아
    **기존과 동일한 문자열**이 나온다.
- **`localStorage` 키에는 버전 접미사를 붙인다.** 스키마가 바뀌면 키가 바뀌므로 낡은
  값을 잘못 읽지 않는다. 회로와 재생 위치 중 **회로만** 저장한다.
- 프리셋은 별도 자료구조 없이 **공유 URL과 같은 직렬화 문자열**로만 갖는다. 로드는
  반드시 undo 스택에 기록해 실수로 눌러도 복구된다.

## 10. QASM / Qiskit 왕복 계약

외부 호환이라 디자인 재작성과 무관하다.

- **매핑 표는 하나뿐이다.** export와 parse가 같은 표를 양방향으로 인덱싱한다. 예전에는
  다섯 군데로 흩어져 있었다 — 역방향 파서가 그 지식을 다시 적으면 export와 parse가
  조용히 갈라져 왕복이 깨진다.
- **정규화는 export 직전과 왕복 비교에 같이 쓴다.** 제어점을 명시적 컨트롤로 접고 빈
  열을 없앤다. **예전 export는 제어점을 통째로 버려 제어가 빠진 다른 회로를 내보내고
  있었다.** 배치 규칙은 파서와 반드시 같아야 한다 — 한쪽이 열 단위 압축, 다른 쪽이
  ASAP이면 정규형이 둘이 되어 왕복 비교가 깨진다.
- **고전 비트도 자원이다.** 빼먹으면 조건부 게이트가 그 조건을 쓰는 측정 **앞으로**
  당겨져 인과가 뒤집힌다(왕복 테스트가 실제로 잡았다).
- **파싱은 전부 성공하거나 아무것도 하지 않는다.** 임시 그리드에만 쌓고 마지막에
  반환하므로 **부분 적용 경로가 코드에 존재하지 않는다.** 에러는 줄 번호 + 구체적
  사유를 준다.
- **`if`의 의미가 OpenQASM과 다르다 — 조용히 넘어가지 않는다.** 이 앱의 조건은 "해당
  비트가 1, 나머지 무관"이고 OpenQASM은 레지스터 전체 값이다. 고전 비트가 2개 이상이면
  달라진다. 그래도 export하는 이유는 1비트로 제한하면 **텔레포테이션 프리셋이 왕복
  불가**가 되기 때문. 대신 **위험할 때만** 경고를 붙인다 — 항상 띄우면 배경 소음이
  되어 정작 필요할 때 안 읽힌다. 경고는 **코드 안 주석과 화면 양쪽**에 넣는다(복사해
  간 사람도 알아야 하므로).
- 동기화는 **단방향 + 명시적 적용**이다. 타이핑 중에는 코드가 거의 항상 문법
  오류이고 undo 스택이 타이핑 단위로 오염된다. 적용은 undo 한 단계여야 한다.
- **Apply 는 사용자가 지우라고 하지 않은 게이트를, 알리지 않고 지우지 않는다.** Apply 는 텍스트에서 회로를
  통째로 다시 만들고, 표현 못 한 게이트의 표시 줄(`// cannot be represented in OpenQASM 2.0: …`)은 주석이라
  그 게이트가 사라진다. 예전엔 한 글자만 고쳐 Apply 해도 아무 말 없이 사라졌다.
  - **판단은 표시 줄로 한다.** 줄이 텍스트에 남아 있으면 지울 뜻이 없었고, 사용자가 직접 지웠으면 지운다는 뜻이다
    (`export.js` `lossesOnApply` — 확인할 것 `unannounced` 와 줄을 지운 것 `lineDeleted`).
  - **줄을 지운 게이트는 확인 없이 지우되, 실행 뒤에 지웠다고 알린다.** 지울 뜻을 잘못 판정했을 때의 비용(조용한 회로
    변경)이 커서, 확인은 건너뛰어도 알림은 건너뛰지 않는다.
  - 표시 줄은 게이트와 큐비트를 적는다. 이름만 적던 때는 다른 큐비트의 CS 두 개가 같은 줄이라 어느 쪽을 지웠는지
    가릴 수 없었다. 열은 적지 않는다 — 텍스트는 정규화된 순서라 위치가 회로의 열이 아니다.
  - **의심스러우면 알린다.** 머리말로 시작하는데 어느 게이트와도 맞지 않는 줄이 남아 있으면(큐비트를 고쳤다든지),
    짝 없는 게이트를 모두 알린다. 지울 뜻이 있었는데 경고하는 비용은 클릭 한 번, 지울 뜻이 없었는데 경고하지 않는
    비용은 조용한 회로 변경이다. 줄 앞뒤 공백은 무시한다.
  - 기록할 고전 비트가 없는 Measure 도 표시 줄을 쓴다. 예전엔 줄을 아예 쓰지 않아 "사용자가 지웠다" 와 구별할 수 없었다.
  - 표시 줄·화면 경고·판정은 한 함수(`unrepresentable`)에서 나온다 — 따로 적으면 내보내기와 판정이 조용히 갈라진다.
  - 해당 게이트가 있으면 Apply 는 한 번 멈추고 무엇이 어디서 사라지는지 알린 뒤 두 번째 누름에 실행한다. 화면 쪽
    규칙(버튼 글자·입력 보호·상태 줄)은 design-spec "패널별 규칙 — 코드 밴드".
- **편집 중의 배너는 숨기지 않고 다시 계산한다.** 편집된 텍스트와 지금 회로로 표시 줄이 남은 표현 불가 게이트만
  경고한다. 예전엔 편집이 시작되면 배너를 감췄다 — 배너가 생성 당시 코드의 설명이라, 편집 중 회로가 바뀌면 낡은
  경고가 남았기 때문이다("superdense 인데 if 경고가 뜬다", 실제로 겪음). 다시 계산하면 낡을 수 없다. 감추던
  사이에는 표현 불가 경고까지 사라져 위의 조용한 삭제를 거들었다. **if 의미 경고만은 편집과 함께 감춘다** — 표시
  줄로 대조할 대상이 아니다.
- 파라미터는 1회 왕복 후 고정점이 되도록 자릿수를 고정한다.
- 코드 패널의 비활성 표현(네이티브 `disabled` 금지 — Apply 가 사유를 툴팁으로 보여야 한다)은
  design-spec "인터랙티브 상태" 절을 따른다.

## 11. 프리셋 검증 원칙

프리셋이 조용히 틀리면 사용자는 알아챌 방법이 없다. 테스트가 **상태벡터를
진폭(실수부·허수부)까지** 대조한다.

- **확률만 보지 않는다.** 위상이 틀려도 확률은 맞을 수 있다. Grover 결과의 부호가 곧
  오라클+확산이 제대로 돌았다는 증거다.
- **기준선 스냅샷 파일**이 프리셋 상태벡터를 고정한다. 의도적으로 바꿀 때만
  갱신한다 — 실제로 QFT를 바꿨을 때 이 스냅샷이 즉시 잡아냈다.
- **QFT 프리셋은 `|000⟩` 입력이 아니다.** 위상이 전부 0이라 H⊗H⊗H와 구별되지 않아
  **QFT의 핵심인 위상 회전이 전혀 드러나지 않는다.**
- **표기 규약을 테스트에 박지 않는다.** Superdense는 "어느 파울리가 어느
  비트열인가"(엔디언 의존)가 아니라 **네 인코딩이 서로 다른 기저 상태에 100%로
  떨어지는가**를 본다 — 그게 프로토콜이 실제로 주장하는 것이다.
- **위상 비교는 값을 접지 말고 차이를 접는다.** `atan2`는 −π와 π를 같은 점으로 주지
  않아, 기대값을 접으면 경계에서 오탐이 난다.

## 12. 축소 밀도행렬

- 선택 큐비트의 축약 밀도행렬을 **전체 2ⁿ×2ⁿ를 만들지 않고 O(2ⁿ)로 2×2만**
  누적한다. 여기서 순도와 블로흐 벡터가 함께 나오며 **DM 뷰와 Bloch sphere가 같은
  계산을 공유한다.**
- 라벨은 **"Mixedness"**(얽힘 아님)를 쓴다 — 다체계에서 |r|<1의 원인이 얽힘만은
  아니므로 정확한 용어여야 한다.
- **전체 밀도행렬은 표시하지 않는다.** 노이즈 없는 시뮬레이터의 상태는 항상 순수라
  전체 행렬은 상태벡터와 정보량이 같고 성분 수만 폭발한다.

## 13. 테스트 제약

- 모델과 UI를 가르는 실질적인 경계는 **Node에서 돌 수 있는가**다. 엔진과 변환
  로직을 DOM 무관한 순수 함수로 짜는 이유가 이것이다.
- **통계 테스트는 `Math.random` 을 쓰지 않는다.** 난수원을 인자로 주입하고(소스의 기본값만
  `Math.random`) 시드를 고정한다 — 실패가 항상 재현되어, 회로가 틀렸는지 운이 나빴는지 가를 수
  있다. 그 위에 단언은 세 종류를 섞는다:
  - **고정 시드의 정확한 값** — 회귀를 못 박는다(궤적 집계의 분포 값, "같은 시드 → 같은 결과").
  - **고정 시드에서 허용 오차 밴드** — 분포가 맞는지 본다("50% 근처지만 정확히 512 는 아님",
    "첫 측정이 대략 50/50"). 정확한 값만 두면 분포가 맞다는 주장이 테스트에 드러나지 않는다.
  - **시드를 바꿔 보는 단언** — 무작위성과 안정성을 본다("시드가 다르면 다른 궤적", "집계는
    시드에 둔감하다").
- 테스트가 무엇을 검증하는지는 `test/`를 직접 읽는다.
