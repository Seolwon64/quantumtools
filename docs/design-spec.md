# 디자인 명세 — UI · 색상 · 레이아웃 · 타이포그래피

디자인과 게이트 팔레트는 처음부터 다시 만들 예정이다. 그래서 구체적인
색값·치수·간격은 걷어냈고, **재작성해도 여전히 참인 제약**과 **예전에 이렇게
틀렸다는 회귀 교훈**만 남겼다. 값이 아니라 이유를 읽어라.

## 1. 아이콘

Lucide(lucide.dev, ISC) 한 세트로 통일한다. 예전에는 이모지 문자와 손으로 그린 SVG가 섞여
있었다.

- npm 패키지를 도입하지 않는다. 빌드 도구가 없는 프로젝트에 아이콘 하나 때문에
  의존성·번들 단계를 들일 이유가 없다. 경로 데이터만 옮겨 담는다.
- 크기·굵기는 상수 두 개가 전부다. 호출부에서 다시 정하거나 CSS로 덮어쓰면 그 순간
  "한 세트"가 깨지고 정의처가 두 곳이 된다.
- **정의처는 한 곳뿐이다.** HTML과 JS에 같은 SVG를 두 벌 두면 반드시 어긋난다 — 3D 씬
  색이 CSS 램프와 어긋났던 것과 같은 실패다.
- 이모지·기하 기호를 UI 아이콘으로 쓰지 않는다. 플랫폼마다 글리프가 달라
  크기·정렬·색을 제어할 수 없다.
- 아이콘은 `aria-hidden`, 의미는 `aria-label`이 전달한다. 보이는 텍스트가 있으면
  `aria-label`이 그것을 포함해야 한다(WCAG 2.5.3).
- **경계:** ⊕ × ⋮ √ ⟨ ⟩ ψ ρ θ φ 는 회로·수학 표기이지 UI 아이콘이 아니다.
  Lucide로 바꾸면 오히려 관례에서 벗어난다.

## 2. 색상 — 3층 구조

역할별로 완전히 분리한다. **예전에는 게이트 색과 인터랙티브 색이 둘 다 파랑이라
"누를 수 있는 것"의 신호가 약했다.**

- **(a) 중립 램프**(배경·테두리·글자) · **(b) 액센트 하나**(누를 수 있는 것 전용) ·
  **(c) 게이트 카테고리**(3장). 게이트에 액센트 색을 쓰지 않는다.
- **차가운 인상은 hue가 아니라 채도가 만든다.** 램프가 차가운 hue였는데도 채도가 너무
  낮아 순수 회색으로 읽히던 시절이 있었다.
- 3D 씬이 이 램프를 읽으므로 구·격자도 함께 따라온다.
- **위험/경고는 전용 토큰으로 분리한다.** 예전에는 게이트 카테고리 색을 빌려
  썼는데, 게이트 색을 조정하면 경고 배너와 Delete가 함께 깨졌다.

## 3. 게이트 카테고리 색

팔레트 칩과 회로 블록이 **같은 변수**를 참조한다. 예전에는 둘로 나뉘어 게이트를
놓기 전후로 색이 달라졌다.

- **탁함(muddy)의 정체는 "중간 명도 + 중간 채도"다.** L=0.62 / C=0.135이던 시절이 그랬다. 둘
  다 올려야 선명해진다 — 한쪽만으로는 해결되지 않는다.
- **채도 상한은 액센트가 정한다.** 카테고리가 액센트만큼 진하면 화면이 형광펜이
  되고 **액센트가 액센트로 기능하지 못한다.**
- **명도를 올리면 채움만으로는 경계가 안 난다.** 패널이 밝아 휘도차가 줄기 때문.
  같은 hue·같은 채도에서 명도만 낮춘 1px 테두리로 경계를 만든다 — 밝기와 경계를
  동시에 얻는 유일한 방법이다. **테스트도 채움이 아니라 테두리를 기준으로 본다.**
- 배경 없는 기호(⊕·×)는 테두리를 빼야 한다 — 없는 상자가 생긴다. 그런데 RCCX/RC3X
  타깃도 ⊕라 같은 선택자에 걸린다. 점선이 CCX와 구분하는 유일한 단서이므로 그
  규칙을 **뒤에** 두어 이기게 한다.

## 4. 타이포그래피

- **폰트는 자체 호스팅한다**(CDN 금지: 서드파티 요청 제거 + FOUT 제어).
- **수학 기호 폴백 — 지우지 마라.** Geist에는 이 앱이 쓰는 ⟨ ⟩ ψ ρ θ φ Φ ⊕
  ⋮ ▾ ⟲ ⚠ ⏮ ⏸ 가 **없다**(cmap 실측). **폰트를 교체하면 이 실측을 다시 해야 한다** — 새 폰트가
  이 글리프를 가질 수도 있고, 그러면 서브셋이 불필요해진다. 지금은 Noto Sans Math / Symbols 2(OFL)에서
  **필요한 코드포인트만 서브셋**해(합계 3KB) 본문 폰트 **뒤**에 두고 있다. `unicode-range`로 범위를 못박아야 본문 폰트가 가진 글자(π·†·√·×·−)를 폴백이 가져가지 않는다. **`fonts/`의 작은 서브셋 파일이
  이것이며 불필요하지 않다.**
- 타입 스케일 변수만 쓰고 **목록 밖의 크기를 새로 만들지 않는다.**
- **등폭을 쓰는 곳을 한 블록에 모아 지정한다** — 숫자 열이 세로로 정렬돼야 하는
  영역 전부. 등폭은 더 넓어 기존 셀에서 줄바꿈이 생길 수 있다.
- **`button/input/select/textarea`는 폰트를 상속하지 않는다.** 명시하지 않으면 그 요소만
  Arial로 렌더된다(실제로 겪음). 전역 규칙으로 `inherit` 시킨다.
- **캔버스 라벨은 폰트 로드 후 다시 그려야 한다.** DOM은 웹폰트가 늦게 와도
  리플로우되지만 **캔버스는 한 번 래스터화되면 끝**이다. 캔버스 폰트 스택은 CSS
  변수와 반드시 일치시킨다.

## 5. 간격 · 반경 · 그림자

- **스케일 변수만 쓰고 하드코딩 px를 남기지 않는다.** 도입할 때 19가지 값 137회가 5종
  137회로 줄었다. 임의로 반올림하지 않는다.
- **허용 예외(주석 필수):** 1px 테두리 · 3D 캔버스 내부 좌표(레이아웃 여백이 아니라
  좌표계다) · 아이콘 광학 보정.
- **그림자 변수의 마지막 레이어가 테두리 역할을 겸한다.** 그래서 이 변수를 쓰는
  요소에 `border`를 따로 주면 2px로 보인다.
- **패널은 그림자로 띄우지 않고 테두리로 면을 나눈다.** 도구 UI에서는 카드가 떠 있는
  느낌보다 면이 나뉜 느낌이 맞다.

## 6. 인터랙티브 상태

클릭 가능한 모든 요소에 **default / hover / active / focus-visible / disabled**를 예외 없이
정의하고 한 블록에 모은다. 도입 전에는 focus-visible이 한 개 요소에만 있었다.

- active에 미세한 축소를 준다 — 누르는 촉감의 핵심이다. 자기 색을 가진 요소는
  중립으로 덮지 않고 **자기 톤 안에서** 진해진다.
- **focus는 `:focus-visible`만** 쓴다. 마우스 클릭엔 링이 뜨지 않는다.
- **비활성에 네이티브 `disabled` 속성을 쓰지 않는다.** 브라우저가 disabled 요소의 마우스
  이벤트를 막아 **사유 툴팁이 아예 뜨지 않는다.** `aria-disabled` + 클래스로 표현하고
  클릭만 JS에서 막는다. 이 규칙은 코드 패널 Apply·재생 버튼·컨텍스트 메뉴 항목에
  **모두** 적용된다.
- **`:not()`은 특이도를 올린다 — 이 함정에 세 번 걸렸다.** `:not()` 세 개를 붙인 중립
  hover 규칙이 `.active` 규칙을 이겨버려 **활성 탭이 hover 시 파란 배경을 잃고 흰 글자만
  남아 라벨이 사라졌다**(대비 1.03). Delete의 빨강이 회색으로 덮인 것도 같은 원인이다.
  자기 색을 가진 변형은 중립 규칙에서 **아예 제외**한다 — 뒤에서 되돌리려 하지
  말고.
- 전환은 `background-color`와 `transform`만 건다. `all`이나 CSS 기본 이징을 쓰지 않는다.
  `prefers-reduced-motion`이면 전환을 사실상 끈다.
- 드래그 가능한 요소는 브라우저가 mousedown 시 `:active`를 취소한다 — 눌림 효과가
  드래그 시작에 보이지 않는 것이 정상이다.

## 7. 패널의 시각적 위계

**데이터가 먼저 보이고 제목·라벨은 배경으로 물러나야 한다.** 눈대중이 아니라 패널
배경 대비 **대비비로 검증한다.**

- **패널 제목들은 값까지 동일해야 한다.** 예전에는 하나가 화면에서 가장 강한
  텍스트였고 다른 둘은 패널 제목보다 굵어 **위계가 역전**돼 있었다.
- 카테고리 라벨은 크기·굵기·대비 **셋 다** 제목보다 낮아야 한다. 하나만 낮추면
  위계가 서지 않는다.
- **데이터를 흐림 단계로 쓰지 않는다.** 큐비트 라벨이 그랬는데 대비가 제목과 똑같아
  "몇 번 큐비트인가"가 제목만큼 뒤로 물러나 있었다.
- **flex 헤더 안의 제목에 `margin-bottom`을 두지 않는다.** flex 아이템의 margin은 정렬 박스에
  포함돼 제목만 위로 밀린다 — 여백은 헤더에 준다.

## 8. 드로어 · 토글

- **메뉴**는 고르면 닫히는 일시적 UI라 오버레이로 뒤를 딤 처리한다. **코드 패널**은
  회로를 보면서 읽으므로 **오버레이를 두지 않는다** — 뒤를 가리면 목적이 사라진다.
- **`display:none`을 드로어에 쓰지 마라.** transition이 실행되지 않아 슬라이드가 통째로
  죽는다 — 정지 화면으로는 똑같아 보여 늦게 발견된다. 닫힘은 `visibility: hidden`(탭
  순서에서도 빠져 접근성에도 맞다).
- **`transform`만 애니메이션한다.** `width`/`left`를 움직이면 매 프레임 레이아웃이 다시
  계산돼 끊긴다.
- **여는 버튼이 드로어보다 위에 있어야 한다.** 열린 상태에서 그 버튼이 곧 닫기인데
  드로어가 덮으면 **마우스로 누를 수 없다**(실제로 겪음). 같은 이유로 포커스
  트랩에도 그 버튼을 포함한다 — 빼면 키보드로 닫기에 도달할 수 없다.
- **자리표시자나 비활성 메뉴 항목을 넣지 않는다.** 미구현 항목이 보이면 앱 전체가
  미완성으로 읽힌다. 테스트가 "coming soon" 문구를 막는다.
- **세그먼트 토글은 선택에 따라 크기가 변하면 안 된다.** 예전에는 한쪽 모드에서만
  나타나는 옆 요소가 토글을 밀어냈고, 줄바꿈 제한이 없어 긴 라벨이 두 줄로 접히며
  토글이 커졌다. **`flex: 1`로는 두 버튼 폭을 못 맞춘다** (컨테이너가 콘텐츠 크기면
  나눠 줄 여유가 0이다) → **grid 균등 트랙**. 양보는 읽기 전용 정보가 하고, 활성
  표시로 `font-weight`를 바꾸지 않는다(폭이 변한다).

## 9. 회로 격자 좌표 — CSS를 베껴 쓰지 않는다

연결선·제어점·기호·배지·스텝 인디케이터의 좌표는 **함수 하나에서만** 나온다.
실제 배치된 셀의 `getBoundingClientRect()`를 읽으므로 CSS를 어떻게 바꿔도 어긋날 수 없다.

**왜 이렇게까지 하는가:** 예전에는 CSS 치수를 상수로 손수 옮겨 적었다. 간격 시스템을
도입하며 padding과 gap이 바뀌었는데 **상수가 갱신되지 않아 연결선이 어긋났다.** 값을
고치는 것으로는 부족하다 — 두 곳에서 계산하는 구조 자체가 원인이다. 패널 최소
높이도 같은 이유로 실측한다.

## 10. 레이아웃 · 그리기 · 애니메이션

- 데스크톱 전용. 모바일 대응은 고려하지 않는다. **칼럼-메이저**를 택한 이유: 직사각
  타일링에서는 행별 독립 칼럼 폭과 칼럼별 독립 행 높이를 동시에 가질 수 없다.
- **X축 라벨 전략은 순수 함수로 분리해 테스트한다.** 판단 기준은 필터를 적용한
  **뒤의 표시 개수**다. 개수가 늘면 단계를 낮추고, 밴드가 좁아 겹칠 상황이면 한 단계
  더 강등해 **어떤 경우에도 라벨이 겹치지 않는다.**
- 이론값과 관측값을 겹쳐 그릴 때 두 계열은 색상이 아니라 **명도로 구분해 색각
  이상에서도 안전하다**(검증 완료).
- **축과 궤적은 `Line`이 아니라 메쉬로 그린다** — WebGL이 `Line`의 두께를 대부분
  무시하기 때문이다.
- **궤적 점 축적 규칙:** 사실상 같은 위치의 점은 추가하지 않는다. 벡터가 정지한
  스텝에서 중복 점이 쌓이면 곡선의 0-접선 때문에 지오메트리가 NaN이 되어 궤적이
  깜빡인다.
- **중간 프레임은 실제 양자 상태가 아니라 시각적 보간일 뿐이다.** 게이트 유니터리를
  분수 적용하지 않는다. 정확한 상태는 전환이 끝난 뒤에만 표시한다.
- **재생 루프는 예외를 가둬야 한다.** `finally`에서 재생·애니메이션 플래그를 반드시
  푼다. 이 불변식이 깨지면 모든 뮤테이션이 플래그 검사에 걸려 **앱 전체가 조작
  불가**가 된다(실제로 겪음 — 예외가 루프 밖으로 새면서 플래그가 true로 고정됐다).
  렌더 예외도 컨트롤러 상태를 오염시키지 못하게 감싼다.
- 회로 편집은 즉시 스냅한다. 애니메이션은 재생·스텝에서만 발생한다.
