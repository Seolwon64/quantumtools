# 디자인 명세 — UI · 색상 · 레이아웃 · 타이포그래피

디자인과 게이트 팔레트는 처음부터 다시 만들 예정이다. 그래서 구체적인
색값·치수·간격은 걷어냈고, **재작성해도 여전히 참인 제약**과 **예전에 이렇게
틀렸다는 회귀 교훈**만 남겼다. 값이 아니라 이유를 읽어라. 값과 그 검산은 `style.css`
토큰 주석에 있다.

- 절은 번호가 아니라 **이름으로** 가리킨다 — 코드 주석도 그렇다. 번호는 절이 늘면 바뀐다.
- 이 문서의 규칙은 **코드의 위반에 맞춰 약하게 고치지 않는다.** 재작성의 입력이라, 규칙을
  지금 코드에 맞추면 재작성이 의도를 잃는다. 알려진 위반과 남은 과제는 `docs/backlog.md` 에 있다.
- 지금 없는 이름은 취소선으로 쓴다(~~`--이름`~~ 꼴 — "회귀 교훈" 절에만 나온다). `test/spec-tokens` 가 이 문서의
  CSS 변수 이름을 `style.css` 와 대조한다 — 취소선이 아닌 이름은 정의돼 있어야 하고, 취소선
  안의 이름은 정의돼 있으면 안 된다.

## 1. 원칙 — 공간 배분

페이지는 절대 스크롤하지 않는다. 공간이 모자라거나 남을 때 누가 양보하고 누가 받는지를
아래 다섯 문장이 정한다. 행·열·코드 밴드가 모두 같은 원칙을 읽는다.

- **우선순위는 회로 > 확률 > Q-sphere > 상태벡터 > 밀도행렬 > 코드 밴드다.** 하단 행 셋은 행
  높이를 공유하므로(3×2 타일링) 순위를 높이가 아니라 **모자랄 때의 반응**으로 표현한다 — 확률은
  내부 스크롤 없이 차트만 줄고, 상태벡터는 항 목록이 스크롤하고, 밀도행렬이 가장 먼저 스크롤을
  받는다. 코드 밴드는 다섯 패널 모두에 양보하는 최하위다 — 접힌 채로는 0px 라 1순위를 밀지 않는다.
  (`layout.js` `rowPlan`·`bandMaxPx`)
- **모자랄 때는 낮은 순위부터 양보하고, 남을 때는 높은 순위부터 각자 "쓸모 있는 최대"까지만
  받는다.** 행은 확률이 쓸모 있는 최대를 받기 전에는 구가 한 픽셀도 못 가져가고, 좁은 화면에서는
  같은 식이 모자랄 때의 규칙과 같은 값을 낸다(식은 `rowPlan` 주석). 열은 1·3열이 콘텐츠 기준
  [최소, 최대] 안에서 비율을 따르고 2열이 나머지를 전부 받는다. 모두 최대에 닿고도 남는 세로는
  하단 행에 둔다 — 큰 확률 차트는 판독을 해치지 않는 가장 무해한 흡수처다. 코드 밴드의 기본
  펼침도 이 흡수처 몫만 가져간다(`bandStartsOpen`). 워크스페이스 max-width 레터박스는 택하지
  않았다 — 남는 공간을 누구에게 줄지 정하지 못하고 1·2순위까지 같이 묶는다.
- **부서지는 쪽을 보호하고 물러날 수 있는 쪽이 양보한다.** 회로는 스크롤로 물러날 수 있고 확률
  차트는 최소 아래에서 읽히지 않는다(부서진다). 그래서 범위가 뒤집히는 낮은 화면에서는 확률
  바닥이 이긴다 — 회로 최소보다(`rowTopPx`), 코드 밴드의 에디터 줄보다(밴드 리사이저). 예외는
  코드 밴드의 충돌 줄 하나다: 적용 안 한 편집이 회로와 어긋났다는 신호와 Reload / Keep 이 거기
  있어 확률 바닥보다 앞선다(`bandMaxPx` 의 바닥).
- **사용자의 드래그가 자동 규칙을 이긴다.** 우선순위 체인과 기본 펼침은 아무것도 안 했을 때의
  기본값이다. 행 드래그 범위는 [회로 최소(크롬 + 한 줄), 확률 최소를 남기는 선]이다 — 하한을 회로
  필요량으로 두면 기본값이 곧 하한인 화면에서 스플리터가 움직이지 않는다. 행은 기본값으로부터의
  **px 오프셋**으로 저장해 화면이 바뀌어도 의도가 같은 양으로 옮겨 가고(비율처럼 불어나지 않는다),
  코드 밴드 높이도 px 로 저장한다(코드 줄 수가 절대 px 다). 더블클릭은 자동 규칙으로 돌아간다.
  기본 펼침은 저장값이 없을 때만 판정하고, 그 결정은 저장하지 않는다.
  (`layout.js` `rowOffsetFor`·밴드 리사이저, `codepanel.js` 기본 펼침)
- **클램프가 곧 지원 범위의 선언이다.** 최소·최대는 CSS 트랙과 드래그 클램프가 **같은 토큰**을
  읽는다(`--col-1-track` 과 `bindSplitter`) — 드래그 쪽만 따로 자르면 CSS 가 멈춘 너머에 핸들이 안
  움직이는 죽은 구간이 생기고, CSS 가 자를 비율을 저장하게 된다. 같은 이유로 회로의 상한, 행
  스플리터의 상한, 코드 밴드의 상한은 **같은 절대 기준**(확률 최소를 남기는 선)을 읽는다 — 하나만
  막으면 나머지 경로로 뚫린다. 범위 밖으로 끈 양은 저장하지 않는다(잘린 뒤의 값을 저장한다 —
  아니면 보이지 않는 빚이 남아 되돌려 끌 때 핸들이 한참 안 움직인다). 세 열 최소의 합이 가장 좁은
  검증 뷰포트에 들어간다는 것이 이 앱이 지원하는 화면의 선언이고, 그 검산은 토큰 주석에 있다.

## 2. 원칙 — 포커스와 Esc

- **용어.** **레이아웃** = 화면 배분에 참여하고 열어 둔 채 다른 일을 하는 영역(패널, 코드 밴드).
  **일시적 UI** = 잠깐 떠서 다른 것을 덮거나, 고르면 닫히는 것(게이트 메뉴, 팝오버, 게이트 정보).
  **대화상자** = 답하기 전에는 뒤를 쓸 수 없는 것 — 지금 앱에는 없다.
- **포커스 트랩은 대화상자만 둔다.** 레이아웃과 일시적 UI 에서 Tab 은 흘러간다. 같은 이유로 코드
  에디터는 Tab 을 들여쓰기로 가로채지 않는다(QASM 은 들여쓰기에 뜻이 없고, 가로채면 앞쪽으로
  빠져나갈 길이 없었다). 뒤를 가리는 딤도 회로를 보면서 쓰는 도구에는 두지 않는다 — 지금 앱에는
  딤이 없다.
- **레이아웃은 Esc 로 닫지 않고, 일시적 UI 는 포커스가 안에 있을 때만 Esc 로 닫는다.** 예전엔
  게이트 정보를 document 전역 Esc 로 닫아, 코드 에디터·팝오버에서 누른 Esc 까지 정보를 닫았다.
  (`gatemenu.js` Operations 패널의 keydown. 코드 밴드에는 Esc 핸들러가 없다.) 게이트 메뉴와
  팝오버는 아직 전역 Esc 다 — `docs/backlog.md`.
- **포커스를 새 자리로 보내는 것은 사용자 조작뿐이다. 자동 동작은 포커스를 건드리지 않는다.**
  사용자가 열면 그 안의 첫 자리로 간다(헤더 Code 버튼 → 코드 영역, Show info → 정보의 닫기 버튼).
  로드 시 자동 펼침·측정·재생은 포커스를 옮기지 않는다 — 옮기면 큰 화면에서 로드하는 순간
  브라우저가 화면 아래 에디터로 스크롤한다.
- **포커스가 있던 요소가 숨거나 다시 그려지면 같은 역할의 자리로 옮긴다.** 옮기지 않으면 body 로
  떨어져 키보드 사용자가 위치를 잃는다. 숨기 **직전에** 안에 있었는지 보고, 숨긴 **뒤에** 옮긴다.
  갈 곳은 역할이 가까운 순으로 찾는다 — 코드 밴드 안 → 헤더 Code 버튼, 게이트 정보 → 연 게이트 →
  같은 자리 게이트 → 회로 그리드. 통째로 다시 그리는 영역(회로 그리드)은 그리기 직전 위치를
  기억해 새 요소로 다시 맞춘다. (`codepanel.js` `keepingFocus`, `gatemenu.js` `dropInfoTarget`·
  `returnFocus`, `grid.js` `buildCircuitGrid`)
- **돌아온 포커스는 보여야 한다.** 포커스를 받는 자리마다(Tab 순서에 없는 `tabindex="-1"` 칩·
  그리드 포함) focus-visible 링이 있다. 링은 `:focus-visible` 에만 그린다. 요소 자체에 그릴 수
  없으면(거터와 한 몸인 코드 에디터, `overflow:hidden` 안이라 잘리는 Qiskit 코드, 스크롤 영역의
  0,0 에 붙어 잘리는 회로 그리드) **감싸개에** 그리고 요소 자신의 링(브라우저 기본 링 포함)은
  끈다 — 안 끄면 이중 링이 된다. 감싸개 선택자는 `:focus-within` 이 아니라
  `감싸개:has(요소:focus-visible)` 다 — `:focus-within` 은 브라우저의 focus-visible 판단을 따르지
  않아, 감싸개 안에 포커스 요소가 더 생기면 마우스 클릭에도 링이 뜬다. (`style.css` 중앙
  focus-visible 블록)
- **코드로 옮긴 포커스의 링은 브라우저가 정한다.** 직전 포커스의 판정을 물려받고, Chromium 은
  수정키 단축키(Ctrl+Z)를 키보드 사용으로 치지 않는다. `focus({ focusVisible: true })` 로 강제하지
  않는다 — 마우스로 누른 뒤에도 링이 떠서 "마우스 클릭엔 링이 뜨지 않는다"를 어긴다.

## 3. 아이콘

Lucide(lucide.dev, ISC) 한 세트로 통일한다. 예전에는 이모지 문자와 손으로 그린 SVG가 섞여
있었다.

- npm 패키지를 도입하지 않는다. 빌드 도구가 없는 프로젝트에 아이콘 하나 때문에
  의존성·번들 단계를 들일 이유가 없다. 경로 데이터만 옮겨 담는다.
- 크기·굵기는 상수 두 개가 전부다. 호출부에서 다시 정하거나 CSS로 덮어쓰면 그 순간
  "한 세트"가 깨지고 정의처가 두 곳이 된다.
- **정의처는 한 곳뿐이다.** HTML과 JS에 같은 SVG를 두 벌 두면 반드시 어긋난다 — 3D 씬
  색이 CSS 램프와 어긋났던 것과 같은 실패다.
- 이모지·기하 기호를 UI 아이콘으로 쓰지 않는다. 플랫폼마다 글리프가 달라
  크기·정렬·색을 제어할 수 없다.
- 아이콘은 `aria-hidden`, 의미는 `aria-label`이 전달한다. 보이는 텍스트가 있으면
  `aria-label`이 그것을 포함해야 한다(WCAG 2.5.3).
- **경계:** ⊕ × ⋮ √ ⟨ ⟩ ψ ρ θ φ 는 회로·수학 표기이지 UI 아이콘이 아니다.
  Lucide로 바꾸면 오히려 관례에서 벗어난다.

## 4. 색상 — 3층 구조

역할별로 완전히 분리한다. **예전에는 게이트 색과 인터랙티브 색이 둘 다 파랑이라
"누를 수 있는 것"의 신호가 약했다.**

- **(a) 중립 램프**(배경·테두리·글자) · **(b) 액센트 하나**(누를 수 있는 것 전용) ·
  **(c) 게이트 카테고리**("게이트 카테고리 색" 절). 게이트에 액센트 색을 쓰지 않는다.
- **"액센트는 누를 수 있는 것 전용"은 의도다.** 지금은 선택 표시·게이트 정보 대상 후광·재생
  진행 점선도 액센트 램프를 쓴다. 이 사용을 규칙에 맞춰 넣지 않는다 — 충돌로 기록해 두었다
  (`docs/backlog.md`, 디자인 재작성 과제).
- **차가운 인상은 hue가 아니라 채도가 만든다.** 램프가 차가운 hue였는데도 채도가 너무
  낮아 순수 회색으로 읽히던 시절이 있었다.
- 3D 씬이 이 램프를 읽으므로 구·격자도 함께 따라온다.
- **위험/경고는 전용 토큰으로 분리한다.** 예전에는 게이트 카테고리 색을 빌려
  썼는데, 게이트 색을 조정하면 경고 배너와 Delete가 함께 깨졌다.

## 5. 게이트 카테고리 색

팔레트 칩과 회로 블록이 **같은 변수**를 참조한다. 예전에는 둘로 나뉘어 게이트를
놓기 전후로 색이 달라졌다.

- **탁함(muddy)의 정체는 "중간 명도 + 중간 채도"다.** L=0.62 / C=0.135이던 시절이 그랬다. 둘
  다 올려야 선명해진다 — 한쪽만으로는 해결되지 않는다.
- **채도 상한은 액센트가 정한다.** 카테고리가 액센트만큼 진하면 화면이 형광펜이
  되고 **액센트가 액센트로 기능하지 못한다.**
- **명도를 올리면 채움만으로는 경계가 안 난다.** 패널이 밝아 휘도차가 줄기 때문.
  같은 hue·같은 채도에서 명도만 낮춘 1px 테두리로 경계를 만든다 — 밝기와 경계를
  동시에 얻는 유일한 방법이다. **테스트도 채움이 아니라 테두리를 기준으로 본다.**
- 배경 없는 기호(⊕·×)는 테두리를 빼야 한다 — 없는 상자가 생긴다. 그런데 RCCX/RC3X
  타깃도 ⊕라 같은 선택자에 걸린다. 점선이 CCX와 구분하는 유일한 단서이므로 그
  규칙을 **뒤에** 두어 이기게 한다.

## 6. 타이포그래피

- **폰트는 자체 호스팅한다**(CDN 금지: 서드파티 요청 제거 + FOUT 제어).
- **수학 기호 폴백 — 지우지 마라.** Geist에는 이 앱이 쓰는 ⟨ ⟩ ψ ρ θ φ Φ ⊕ ⋮ 가 **없다**
  (cmap 실측). **폰트를 교체하면 이 실측을 다시 해야 한다** — 새 폰트가 이 글리프를 가질 수도
  있고, 그러면 서브셋이 불필요해진다. 지금은 Noto Sans Math / Symbols 2(OFL)에서 **필요한
  코드포인트만 서브셋**해 본문 폰트 **뒤**에 두고 있다. `unicode-range`로 범위를 못박아야 본문
  폰트가 가진 글자(π·†·√·×·−)를 폴백이 가져가지 않는다. **`fonts/`의 작은 서브셋 파일이
  이것이며 불필요하지 않다.** 서브셋에는 아이콘을 Lucide 로 바꾸기 전에 쓰던 ▾ ⟲ ⚠ ⏮ ⏸ 도
  남아 있다 — 지금 UI 에는 없다(정리는 `docs/backlog.md`).
- 타입 스케일 변수만 쓰고 **목록 밖의 크기를 새로 만들지 않는다.**
- **등폭을 쓰는 곳을 한 블록에 모아 지정한다** — 숫자 열이 세로로 정렬돼야 하는
  영역 전부. 등폭은 더 넓어 기존 셀에서 줄바꿈이 생길 수 있다.
- **`button/input/select/textarea`는 폰트를 상속하지 않는다.** 명시하지 않으면 그 요소만
  Arial로 렌더된다(실제로 겪음). 전역 규칙으로 `inherit` 시킨다.
- **캔버스 라벨은 폰트 로드 후 다시 그려야 한다.** DOM은 웹폰트가 늦게 와도
  리플로우되지만 **캔버스는 한 번 래스터화되면 끝**이다. 캔버스 폰트 스택은 CSS
  변수와 반드시 일치시킨다.

## 7. 간격 · 반경 · 그림자

- **스케일 변수만 쓰고 하드코딩 px를 남기지 않는다.** 도입할 때 19가지 값 137회가 5종
  137회로 줄었다. 임의로 반올림하지 않는다.
- **허용 예외(주석 필수):** 1px 테두리 · 3D 캔버스 내부 좌표(레이아웃 여백이 아니라
  좌표계다) · 아이콘 광학 보정.
- **그림자 변수의 마지막 레이어가 테두리 역할을 겸한다.** 그래서 이 변수를 쓰는
  요소에 `border`를 따로 주면 2px로 보인다.
- **패널은 그림자로 띄우지 않고 테두리로 면을 나눈다.** 도구 UI에서는 카드가 떠 있는
  느낌보다 면이 나뉜 느낌이 맞다.

## 8. 인터랙티브 상태

클릭 가능한 모든 요소에 **default / hover / active / focus-visible / disabled**를 예외 없이
정의하고 한 블록에 모은다. 도입 전에는 focus-visible이 한 개 요소에만 있었다.

- active에 미세한 축소를 준다 — 누르는 촉감의 핵심이다. 자기 색을 가진 요소는
  중립으로 덮지 않고 **자기 톤 안에서** 진해진다.
- **focus는 `:focus-visible`만** 쓴다. 마우스 클릭엔 링이 뜨지 않는다. 링을 감싸개에 그리는
  경우와 코드로 옮긴 포커스는 "원칙 — 포커스와 Esc" 절.
- **비활성에 네이티브 `disabled` 속성을 쓰지 않는다.** 브라우저가 disabled 요소의 마우스
  이벤트를 막아 **사유 툴팁이 아예 뜨지 않는다.** `aria-disabled` + 클래스로 표현하고
  클릭만 JS에서 막는다. 이 규칙은 코드 패널 Apply·재생 버튼·컨텍스트 메뉴 항목에
  **모두** 적용된다. 알려진 위반(한계에 닿은 큐비트 −/+ 등)은 `docs/backlog.md`.
- **`:not()`은 특이도를 올린다 — 이 함정에 세 번 걸렸다.** `:not()` 세 개를 붙인 중립
  hover 규칙이 `.active` 규칙을 이겨버려 **활성 탭이 hover 시 파란 배경을 잃고 흰 글자만
  남아 라벨이 사라졌다**(대비 1.03). Delete의 빨강이 회색으로 덮인 것도 같은 원인이다.
  자기 색을 가진 변형은 중립 규칙에서 **아예 제외**한다 — 뒤에서 되돌리려 하지
  말고.
- **전환은 레이아웃을 매 프레임 다시 계산하지 않는 속성에만 건다** — `background-color`·
  `transform`·`opacity`. `width`·`height`·`left` 를 움직이면 매 프레임 레이아웃이 다시 계산돼
  끊긴다. `all`이나 CSS 기본 이징을 쓰지 않고, 시간과 이징은 토큰(`--dur`·`--ease`)으로 준다.
  `prefers-reduced-motion`이면 전환을 사실상 끈다. 알려진 위반(확률 막대 높이·혼합도 막대 폭
  전환, `ease`)은 `docs/backlog.md`.
- 드래그 가능한 요소는 브라우저가 mousedown 시 `:active`를 취소한다 — 눌림 효과가
  드래그 시작에 보이지 않는 것이 정상이다.

## 9. 패널의 시각적 위계

**데이터가 먼저 보이고 제목·라벨은 배경으로 물러나야 한다.** 눈대중이 아니라 패널
배경 대비 **대비비로 검증한다.**

- **패널 제목들은 값까지 동일해야 한다.** 예전에는 하나가 화면에서 가장 강한
  텍스트였고 다른 둘은 패널 제목보다 굵어 **위계가 역전**돼 있었다.
- 카테고리 라벨은 크기·굵기·대비 **셋 다** 제목보다 낮아야 한다. 하나만 낮추면
  위계가 서지 않는다.
- **데이터를 흐림 단계로 쓰지 않는다.** 큐비트 라벨이 그랬는데 대비가 제목과 똑같아
  "몇 번 큐비트인가"가 제목만큼 뒤로 물러나 있었다.
- **flex 헤더 안의 제목에 `margin-bottom`을 두지 않는다.** flex 아이템의 margin은 정렬 박스에
  포함돼 제목만 위로 밀린다 — 여백은 헤더에 준다.

## 10. 패널별 규칙 — 코드 밴드 · 게이트 정보 · 토글

공간 배분과 포커스의 일반 규칙은 두 원칙 절에 있다. 여기는 패널마다 고유한 사실만 둔다.

- **코드 패널은 3×2 그리드 아래 전폭 밴드다.** 회로를 보면서 읽고 고치는 도구라 **오버레이를
  두지 않는다** — 뒤를 가리면 목적이 사라진다. `#ws-grid` 의 **형제**라 1열(팔레트·밀도행렬)은
  늘 보이고, 밴드가 가져간 높이만큼 그리드가 줄면 행 배분(`rowPlan`)이 줄어든 높이로 다시
  나눈다. 그리드의 네 번째 행으로 넣지 않은 것은 행 배분이 밴드까지 떠안지 않게 하려는 것이다.
  - **입구는 헤더의 Code 버튼 하나다.** 유일한 입구라 아이콘만 두면 찾기 어려워 보이는 글자
    "Code" 를 함께 둔다. 아이콘은 장식(aria-hidden)이고, aria-label 은 보이는 글자로 시작한다
    (WCAG 2.5.3 — 음성으로 "Code 클릭"이 통해야 한다). `aria-expanded`·`aria-controls` 가 밴드를
    가리킨다. 밴드가 접힌 채 적용 안 한 편집이나 충돌이 있으면 **표시 점**을 달고 aria-label 에도
    그 사실을 넣는다("Code, unapplied edits").
  - **접힌 밴드는 0px 다** — 밴드와 그 위 간격(리사이저)까지 `hidden`. 6단계에는 접힌 머리글이
    63px(51 + 간격 12)를 가져가 1536×740 · 4큐비트 회로가 49px 스크롤됐다 — 최하위가 접힌 채로
    1순위를 민 것이다. 예외는 충돌 줄("Circuit changed" + Reload / Keep) 하나다 — 머리글·몸통
    밖에 있어 접힌 채로 그 줄만 보인다. 머리글(탭·Apply·Copy·접기)은 펼쳤을 때만 있다.
  - **접힘·펼침은 즉시다.** 높이를 애니메이션하면 밴드 → 그리드 → 행 배분·차트·구가 매 프레임
    다시 계산된다("인터랙티브 상태" 절의 전환 규칙). 그래서 `hidden`(`display:none`)을 써도
    된다 — 아래 "숨기는 방법" 참고. 전환을 붙이려면 이 전제부터 다시 봐야 한다.
  - **포커스.** 트랩도 Esc 도 없다(레이아웃). 헤더 버튼으로 펼치면 코드 영역(Qiskit 탭이면 읽기
    전용 코드)으로 간다 — 화면 아래 밴드까지 그리드 전체를 Tab 으로 지나가지 않게. 헤더 버튼으로
    접으면 그 버튼에 남는다. 밴드 안에 있던 포커스가 숨게 되면(접기 버튼·에디터·충돌 줄 버튼)
    헤더 버튼으로 옮긴다 — 밴드가 펼친 채 남으면 코드 영역으로.
  - **높이 권한은 행 스플리터와 같다**("원칙 — 공간 배분"). 상한 = 워크스페이스 − 간격 − 회로
    최소 − 확률 최소이고, 상한의 바닥은 **접힌 밴드의 실측 높이**(평소 0, 충돌 줄이 떠 있으면 그
    줄)다. 리사이저 더블클릭은 기본(에디터 16줄)으로 돌린다.
  - **밴드 안 우선순위는 머리글 > 충돌 줄 > 상태 줄 > 에디터 줄이다.** 에디터는 `height` 가
    아니라 flex-basis 로 크기를 가져야 밴드의 `max-height` 가 에디터를 줄일 수 있다. 상태 줄은
    Apply 결과·파싱 에러를 보여 주는 자리라 줄지 않고, 공간이 모자라면 에디터가 3줄 아래로라도
    줄어 스크롤된다(3줄은 드래그 하한일 뿐 CSS 바닥이 아니다).
  - **기본 펼침은 고정 임계가 아니라 배분으로 정한다.** 저장값이 없을 때만, 로드 시 한 번 —
    기본 높이로 펼쳐도 회로가 스크롤되지 않고, 확률이 쓸모 있는 최대를 유지하고, Q-sphere 가
    줄지 않으면 펼친다. Δ 는 "그리드가 잃는 높이"를 그대로 잰다 — 접힌 밴드가 0px 라 밴드와 그
    위 간격이 함께 들어간다. 판정용으로 한 번 펼쳐 재는 동작은 저장·포커스를 타지 않는다.
  - **긴 줄은 화면에서만 줄바꿈한다**(`pre-wrap` + textarea 기본 soft wrap). 값에 개행을 넣으면
    Apply 왕복이 깨진다. 거터 번호와 에러 띠는 숨은 미러로 잰 줄별 높이를 따르고, 미러 폭은
    `textarea.clientWidth` 실측이다(`scrollbar-gutter` 는 스크롤 컨테이너에만 걸려 CSS 로 맞추면
    스크롤바 폭만큼 어긋난다).
- **게이트 정보(Show info)는 팔레트를 잠깐 덮는 일시적 UI 다 — 대화상자가 아니다.** `role="region"`
  에 이름은 보이는 제목(게이트 이름, `aria-labelledby`)이고 `aria-modal` 이 없다. 포커스 트랩·딤·
  전환이 없다(즉시 바뀐다). 덮인 팔레트는 `display:none` 이라 Tab 순서에서도 빠진다 — Tab 은
  닫기 버튼 → 행렬 → 회로 패널로 흘러간다.
  - **포커스.** 열면 닫기 버튼으로 간다. 닫으면(닫기 버튼·Esc) ① 정보를 연 게이트 ② 같은 자리에
    지금 놓인 게이트 ③ 회로 그리드 순으로 돌려보낸다. "같은 자리"는 홈 칸이 먼저고, 비었으면 같은
    열에서 그 게이트가 쓰던 다른 큐비트다 — RCCX 를 펼치면 첫 단계가 타깃 줄에 놓인다. 저절로 닫힐
    때(삭제·Undo·프리셋·Apply expansion)는 포커스가 정보 안에 있었을 때만 같은 규칙으로 옮긴다.
    칩·제어점·그리드는 `tabindex="-1"` — 포커스는 받지만 Tab 순서엔 없다.
  - **그리드를 다시 그려도 포커스를 지킨다.** `buildCircuitGrid` 가 렌더마다 그리드를 비우고 새로
    만들어, 돌려보낸 포커스가 다음 렌더(재생 스텝·편집)에 body 로 떨어졌다. 정보 패널도 같은
    이유로 내용이 같으면 다시 그리지 않는다(행렬의 포커스·스크롤 위치가 남는다).
  - **대상은 자리가 아니라 게이트로 알아본다**(종류·대상·제어 — `isSameGate`). 같은 자리에 다른
    게이트가 오면 지워진 것처럼 닫고, 파라미터만 바뀐 같은 게이트는 열린 채 갱신한다. 예전엔 자리로만
    봐서 Undo·프리셋 뒤 정보가 조용히 다른 게이트의 것으로 바뀌었다.
  - **대상 표시는 선택과 따로 간다.** `.info-target` 은 `box-shadow` 후광, 선택(`.selected`)과 포커스
    링은 `outline` 이라 셋이 겹쳐도 다 보인다. 예전엔 정보가 선택 강조에 기대서, 빈 칸을 누르거나 다른
    게이트의 메뉴를 열면 무엇에 대한 정보인지 회로에서 사라졌다.
  - **가로 스크롤은 행렬에만, 세로 스크롤은 정보 전체에.** 예전엔 정보 전체가 양축으로 스크롤해 넓은
    행렬을 밀면 제목·설명이 함께 밀려 나갔다. 행렬 상자(`.mx-scroll`)는 키보드로도 밀 수 있게 Tab
    순서에 있고 이름("Unitary matrix")이 있다. 이 상자는 `flex: none` 이어야 한다 — overflow 가
    visible 이 아닌 flex 아이템은 자동 최소 높이가 0 이라, 그대로 두면 정보 높이에 짓눌려 **행렬
    안에서** 세로 스크롤됐다(중첩 스크롤, 그 스크롤바가 행렬 폭을 15px 깎았다). 글자는 줄이지 않는다.
    8×8 을 넘는 행렬(RC3X 16×16)은 그리지 않고 크기와 그 사실을 말한다.
  - **1열 최대는 8×8 행렬이 가로 스크롤 없이 다 보이는 선이다**(검산은 `--col-1-max` 주석).
    행렬 칸이나 행렬 포매터를 넓히는 변경은 이 선을 넘긴다 — 지금 여유는 "알려진 한계" 절.
- **숨기는 방법은 이유로 고른다.** 세 경우가 반대처럼 보이지만 근거가 다르다.
  - 전환이 있는 요소는 `display:none` 을 쓰지 않는다 — transition 이 실행되지 않아 정지 화면으로는
    똑같아 보이는 채 전환이 통째로 죽는다(회귀 교훈 절의 슬라이드 패널). 닫힘은 `visibility: hidden`.
  - 모드에 따라 갈아 끼우는 요소는 같은 칸에 겹쳐 `visibility` 로 숨긴다(아래 모드별 요소).
  - 그 밖에 즉시 사라져도 되고 자리를 비워야 하는 것(접힌 코드 밴드, 게이트 정보 ↔ 팔레트)은
    `hidden`·`display:none` 이다 — Tab 순서에서도 함께 빠진다.
- **자리표시자나 비활성 항목을 UI 어디에도 넣지 않는다.** 미구현 항목이 보이면 앱 전체가
  미완성으로 읽힌다. 처음엔 한 목록에만 걸던 규칙을 UI 전체로 넓혔다 — 테스트(`test/ui-invariants`)가
  `index.html` 과 `js/*.js` 전부에서 "coming soon" 문구를 막는다.
- **세그먼트 토글은 선택에 따라 크기가 변하면 안 된다.** 예전에는 한쪽 모드에서만
  나타나는 옆 요소가 토글을 밀어냈고, 줄바꿈 제한이 없어 긴 라벨이 두 줄로 접히며
  토글이 커졌다. **`flex: 1`로는 두 버튼 폭을 못 맞춘다** (컨테이너가 콘텐츠 크기면
  나눠 줄 여유가 0이다) → **grid 균등 트랙**. 양보는 읽기 전용 정보가 하고, 활성
  표시로 `font-weight`를 바꾸지 않는다(폭이 변한다).
- **모드별로 나타나는 요소는 `display`로 빼지 말고 같은 칸에 겹쳐 `visibility`로 숨긴다.**
  구 패널 하단 줄에서 Bloch 정보 블록과 Q-sphere 위상 범례를 `display:none`으로 갈아
  끼웠더니, 3열이 좁을 때 한쪽 모드만 줄이 접혀 하단 높이가 89↔41px로 바뀌었고 캔버스가
  모드 전환마다 흔들렸다. 한 칸에 겹치면 칸 크기가 CSS만으로 늘 두 요소 중 큰 쪽이 된다.
- **큐비트 선택은 두 패널(구·밀도행렬) 모두 같은 드롭다운이다.** 같은 전역 값을 조작하는
  위젯이 모양까지 달랐고, 구 패널의 탭 여섯 개는 3열 최소를 약 350px로 올렸다.

## 11. 회로 격자 좌표 — CSS를 베껴 쓰지 않는다

연결선·제어점·기호·배지·스텝 인디케이터의 좌표는 **함수 하나에서만** 나온다.
실제 배치된 셀의 `getBoundingClientRect()`를 읽으므로 CSS를 어떻게 바꿔도 어긋날 수 없다.

**왜 이렇게까지 하는가:** 예전에는 CSS 치수를 상수로 손수 옮겨 적었다. 간격 시스템을
도입하며 padding과 gap이 바뀌었는데 **상수가 갱신되지 않아 연결선이 어긋났다.** 값을
고치는 것으로는 부족하다 — 두 곳에서 계산하는 구조 자체가 원인이다. 패널 최소
높이도 같은 이유로 실측한다.

**그리드 밖 크롬 높이도 실측한다.** `.circuit-scroll`이 `flex: 1`이라 패널이 커지면 스크롤
영역만 커지고 크롬(툴바·재생·패딩·가로 스크롤바)은 그대로다 — 차분이 일정해 행 배분이
측정값을 바꾸는 되먹임이 없다. 크롬 = 패널 높이 − 스크롤 영역의 내용 높이(가로 스크롤바를 뺀
높이)다. 높이는 전부 소수로 재고, 가로 스크롤바 두께만 `offsetHeight − clientHeight`(둘 다
정수지만 차이는 정확하다)로 뺀다 — 이유는 "측정 규칙" 절. 확률 패널(`− .prob-chart`)도 같은
방식이다(`layout.js` `measureRows`). 크롬을 토큰으로 박아 두었다가 틀린 이력은 "회귀 교훈" 절.

**행 높이는 `layout.js` 한 곳에서 px로 정한다.** 1부에서는 회로 패널의 인라인
`min-height`가 auto 최소인 상단 행을 밀어 올렸는데, 그러면 사용자가 스플리터로 상단을
줄여도 **되밀려 돌아와** 스플리터가 죽은 컨트롤이 됐다. 지금은 측정·우선순위 체인·
관찰(ResizeObserver)이 전부 `layout.js`에 있고 `--row-top`을 px로 쓴다. `main.js`는
`render` 끝에서 `relayout()`만 부른다. 크롬은 `render`를 거치지 않는 경로(Hide 0%,
샘플링, Show all, 코드 밴드 펼침·높이·충돌 줄, 열 드래그, 창 크기)로도 바뀌므로 **경로를 쫓지 않고 크롬을
이루는 요소 자체**(`#ws-grid`, 두 툴바, 재생 줄, 확률 푸터)를 관찰한다. 이 요소들의
크기는 열 폭과 내용으로만 정해져 행 배분이 다시 관찰을 부르는 고리가 없다.

**대신 스크롤바 결합 고리를 끊어 두어야 한다.** 양축이 `auto`면 세로 스크롤바 유무 →
`clientWidth` → 가로 스크롤바 유무 → `clientHeight` 로 고리가 돌아 크롬 측정값이
진동한다. `.circuit-scroll`의 `scrollbar-gutter: stable`이 그 첫 단계를 막는다 — 지우지 마라.

## 12. main.js 배선 순서 — 컨트롤러가 생성 도중에 render를 부른다

`createCircuitController`가 **반환 직전에 `render`를 한 번 부른다.** 그래서 `render`가
쓰는 이름이 그 시점에 이미 초기화돼 있어야 한다. 구조분해로 받는 `const`는 평가 전까지
TDZ에 있어, 순서를 어기면 **모듈 최상위에서 ReferenceError가 나고 앱이 통째로 뜨지
않는다.** 미묘한 버그가 아니라 백지 화면이다.

- `initGateMenu` · `initProbView` · `initPlayback` · `initGrid` 는 컨트롤러보다 **먼저**
  배선한다. `initGrid`는 `attachIndicator`·`stepIndicatorX`를 받으므로 `initPlayback`
  **뒤**여야 한다.
- 팝오버는 `circuit`을 클로저로 잡으므로 컨트롤러 **뒤**에 배선한다. 앞선 모듈들이
  팝오버 함수를 필요로 하므로 **화살표로 감싸 넘겨** 호출 시점에 이름이 풀리게 한다.
- `codePanel`은 `const`가 아니라 `let ... = null`이다. `render`가
  `codePanel?.onCircuitChanged()`를 부르는데, `const`면 그 시점이 TDZ다. **`?.`로도 막지
  못한다** — 옵셔널 체이닝은 값이 `null`일 때를 막지 이름이 미초기화일 때를 막지 않는다.
- `showToast`는 `function` 선언이라 호이스팅되어 정의보다 앞에서 참조된다.
  `const showToast = ...`로 바꾸면 로드 시 TDZ 에러가 난다.

**자동으로 잡히지 않는다.** 문법은 완벽히 유효해 Stop 훅의 `node --check` 전수 검사를
통과하고, 테스트는 DOM 배선을 덮지 않는다. 앱을 띄워 콘솔을 보는 것이 유일한 검출
경로다.

## 13. 레이아웃 · 그리기 · 애니메이션

공간을 누구에게 줄지는 "원칙 — 공간 배분" 절에 있다.

- 데스크톱 전용. 모바일 대응은 고려하지 않는다. 워크스페이스는 **3열 2행 직사각
  타일링**이다. 직사각 타일링에서는 행별 독립 칼럼 폭과 칼럼별 독립 행 높이를 동시에
  가질 수 없다 — **행 비율을 세 열이 공유**하는 쪽을 택했고(가로 스플리터가 하나뿐인
  이유가 이것이다), 칼럼-메이저 flex 였던 시절에는 반대쪽을 택했었다.
- **X축 라벨 전략은 순수 함수로 분리해 테스트한다.** 판단 기준은 필터를 적용한
  **뒤의 표시 개수**다. 개수가 늘면 단계를 낮추고, 밴드가 좁아 겹칠 상황이면 한 단계
  더 강등해 **어떤 경우에도 라벨이 겹치지 않는다.**
  **높이도 같은 사다리의 조건이다.** 45°는 하단 46px를 쓰는데 낮은 화면에서 그걸 주면
  플롯이 읽히지 않는다 — 그때는 sparse로 한 단계 더 내려 **라벨을 잘라 보여주지 않는다.**
  확률 패널의 최소 높이를 sparse 기준으로 잡을 수 있는 근거가 이 강등이고, 모드가 바뀌어도
  **어떤 박스 높이도 변하지 않아야 한다**(변하면 높이 → 모드 → 높이로 되먹임이 생긴다).
- **툴바는 항목 단위로 줄바꿈한다.** 버튼 안 글자가 접히면 안 된다(`white-space: nowrap`).
  함께 있어야 뜻이 되는 컨트롤(되돌리기·다시하기·공유, Inspect·궤적 배지)은
  `.toolbar-group`으로 감싸 한 덩어리로 넘어간다. 2열 최소는 그 뒤 **가장 넓은 한 묶음**이다.
- 이론값과 관측값을 겹쳐 그릴 때 두 계열은 색상이 아니라 **명도로 구분해 색각
  이상에서도 안전하다**(검증 완료).
- **축과 궤적은 `Line`이 아니라 메쉬로 그린다** — WebGL이 `Line`의 두께를 대부분
  무시하기 때문이다.
- **세로형 캔버스에서는 세로 시야각을 넓혀 가로 시야를 고정한다.** `PerspectiveCamera`의
  `fov`는 세로 기준이라, 그대로 두면 구가 높이에 맞춰 커지고 좁은 3열에서 좌우가 잘렸다.
  보정하면 구가 `min(폭, 높이)`에 맞는다. 하단 줄이 접혀 캔버스를 양보할 때 "구가 가려지는
  대신 작아진다"가 성립하는 것도 이 보정 덕분이다.
- **궤적 점 축적 규칙:** 사실상 같은 위치의 점은 추가하지 않는다. 벡터가 정지한
  스텝에서 중복 점이 쌓이면 곡선의 0-접선 때문에 지오메트리가 NaN이 되어 궤적이
  깜빡인다.
- **중간 프레임은 실제 양자 상태가 아니라 시각적 보간일 뿐이다.** 게이트 유니터리를
  분수 적용하지 않는다. 정확한 상태는 전환이 끝난 뒤에만 표시한다.
- **재생 루프는 예외를 가둬야 한다.** `finally`에서 재생·애니메이션 플래그를 반드시
  푼다. 이 불변식이 깨지면 모든 뮤테이션이 플래그 검사에 걸려 **앱 전체가 조작
  불가**가 된다(실제로 겪음 — 예외가 루프 밖으로 새면서 플래그가 true로 고정됐다).
  렌더 예외도 컨트롤러 상태를 오염시키지 못하게 감싼다.
- 회로 편집은 즉시 스냅한다. 애니메이션은 재생·스텝에서만 발생한다.

## 14. 측정 규칙

레이아웃 재설계(1~8단계)에서 측정이 틀렸던 경우를 규칙으로 남긴다. 디자인 재작성의 검증에서
그대로 다시 쓴다.

- **뷰포트는 기기 이름이 아니라 `innerWidth × innerHeight` 로 부른다.** 같은 기기라도 브라우저
  크롬·배율에 따라 안쪽 크기가 다르다. 검증 뷰포트는 다섯이다 — 1366×640, 1536×740, 1920×950,
  2560×1300, 3840×2000.
- **넘침은 상자가 아니라 텍스트로 잰다**(Range 의 `getClientRects`). 상자는 안 넘쳐도 글자는
  넘칠 수 있고, 상자가 넘쳐도 비어 있는 부분일 수 있다.
- **정수와 소수를 섞지 않는다.** `clientHeight`·`offsetHeight` 는 정수로 반올림되고
  `getBoundingClientRect()` 는 소수다. 둘을 빼면 ±0.5px 가 흔들린다 — 확률 차트 바닥 96px 이
  95.5px 로 뚫렸고, 거터 줄 높이를 줄마다 더하자 6px 이 밀렸다. 높이는 소수로 재고, 정수 둘의
  **차이**(스크롤바 두께)만 정수로 쓴다.
- **지표가 무의미하지 않은지 반드시 실패해야 하는 대조군으로 먼저 확인한다.** 루트가
  `overflow:hidden` 이라 "페이지 스크롤" 은 무엇을 해도 0 이었다 — 그 지표로는 아무것도 검증하지
  못한다. 새 검사는 일부러 깨뜨린 입력에서 실패하는 것을 본 뒤에 믿는다.
- **기본값을 재기 전에 저장 키를 지운다.** 새로고침은 `localStorage` 를 지우지 않는다. 지운 키와
  그 전 값을 함께 기록한다. 사용자 경로로 조작하면(헤더 버튼 등) 다시 저장되므로 다음 측정
  전에 또 지운다.
- **언제 쟀는지가 값을 바꾼다.** 코드 패널을 연 채 render 된 값이 닫은 뒤에도 남았다. 상태를
  바꾼 뒤에는 정착(관찰 → 다음 프레임 재배분)을 기다려 다시 잰다.
- **순간 현상과 정착 상태를 구분한다.** 창을 빠르게 줄이면 두 프레임 동안 34px 이 넘쳤다가
  정착한다. 순간 현상인지 정착 상태인지 적고, 고칠지는 그 구분으로 정한다.
- **드라이버의 실수를 측정으로 착각하지 않는다.** 누르는 좌표가 다른 요소(스크롤바·거터·겹친
  패널)에 걸리면 앱이 아니라 드라이버가 틀린 것이다 — `elementFromPoint` 로 무엇을 누르는지
  확인하고, 화면 밖 요소는 스크롤해 보이게 한 뒤 누른다.

## 15. 회귀 교훈 — 지금 없지만 다시 만들 때

지금은 해당하는 요소가 없다. 같은 것을 다시 만들면 그때 지킨다.

- **메뉴 드로어(햄버거)** — 7단계에서 없앴다. 항목이 Code editor 하나뿐이었고, 그 입구를 헤더의
  Code 버튼으로 옮기자 드로어에 남는 것이 없었다. 드로어(또는 슬라이드하는 패널)를 다시 만들면:
  - **고르면 닫히는 일시적 UI 만 오버레이로 뒤를 딤 처리한다.** 회로를 보면서 쓰는 도구에는
    두지 않는다(코드 밴드).
  - **`display:none`을 드로어에 쓰지 마라.** transition이 실행되지 않아 슬라이드가 통째로
    죽는다 — 정지 화면으로는 똑같아 보여 늦게 발견된다. 닫힘은 `visibility: hidden`(탭
    순서에서도 빠져 접근성에도 맞다).
  - **`transform`만 애니메이션한다.** `width`/`left`를 움직이면 매 프레임 레이아웃이 다시
    계산돼 끊긴다.
  - **여는 버튼이 드로어보다 위에 있어야 한다.** 열린 상태에서 그 버튼이 곧 닫기인데
    드로어가 덮으면 **마우스로 누를 수 없다**(실제로 겪음).
  - **대화상자 드로어는 포커스를 가두고, 그 순환에 여는 버튼을 포함한다** — 빼면 키보드로
    닫기에 도달할 수 없다. 레이아웃에 참여하는 패널(코드 밴드)에는 트랩을 두지 않는다.
- **1열을 접는 코드 드로어** — 코드 패널이 그리드 왼쪽에 끼는 드로어였을 때는 열면 1열(팔레트·
  밀도행렬)을 접었다. 6단계에 그리드 아래 밴드로 옮겼다. 다시 옆에 붙이면 "1열은 늘 보인다"가
  깨지고 행 배분이 아니라 열 배분이 밴드를 떠안는다.
- **크롬 높이 토큰(~~`--circuit-chrome`~~)** — 한동안 "이것만은 실측할 수 없다 — 계산 결과를 행
  높이로 되돌려 쓰므로 되먹임이 생긴다"고 보고 크롬을 토큰에 적어 두었는데, **그 전제가
  틀렸다**(차분이 일정하다 — "회로 격자 좌표" 절). 토큰으로 박아 둔 값은 **가로 스크롤바가 없던
  화면에서 잰 것이라 좁은 화면에서 12px를 과소평가**했고, 그만큼 회로가 세로로 잘렸다.
- **비율로 정한 열 최소(~~`--col-min`~~)** — 열 최소를 `fr` 비율로 두면 화면이 좁아질 때 px 로도
  줄어, 1280 에서 3열이 상태벡터가 잘리는 폭까지 떨어졌다. 지금은 콘텐츠 기준 px 최소·최대다
  (`style.css` 열 토큰 주석).

## 16. 알려진 한계 — 고치지 않기로 한 것과 그 이유

아직 안 고친 것(규칙 위반·과제)은 여기가 아니라 `docs/backlog.md` 에 있다. 여기는 고치지
**않기로** 정한 것이다.

- **1366×640 에서 코드 밴드 상한이 리사이저 드래그 최소보다 작다.** 상한 122px < 최소(에디터
  3줄) 161.8px(빈 회로, 저장 키 삭제, 9단계 실측). 상한이 이겨 에디터가 3줄 아래로 줄어
  스크롤된다. 1536×740 부터는 뒤집히지 않는다(상한 237px). **이유:** 확률 바닥이 에디터 줄보다
  앞선다("원칙 — 공간 배분"의 부서지는 쪽 보호).
- **8×8 행렬의 여유가 −0.1px 다.** 1열 최대에서 정보가 세로로 스크롤되는 낮은 화면(1366×640)은
  세로 스크롤바만큼 행렬 자리가 480px 로 줄고 행렬 자연 폭은 480.1px 이다. Chrome 은
  `scrollWidth` 를 정수로 반올림해 가로 스크롤바를 띄우지 않는다(8단계 실측). **이유:** 보이는
  결과가 맞고, 1열 최대를 넓히면 열 배분 전체가 움직인다.
- **그리드를 다시 그린 뒤의 재포커스는 매번 새 요소에 포커스를 준다** — 재생 중 스크린리더가
  스텝마다 게이트를 다시 읽을 수 있다. **이유:** 근본 해결은 그리드를 통째로 다시 그리지 않는
  것이고, 회로 키보드 탐색과 함께 할 일이다(`docs/backlog.md`).
- **마우스로 연 게이트 정보가 곧바로 Ctrl+Z 로 닫히면 포커스는 칩으로 가지만 링이 뜨지 않는다.**
  **이유:** 강제하면 마우스로 누른 뒤에도 링이 뜬다("원칙 — 포커스와 Esc").
- **창을 빠르게 줄이면 두 프레임 동안 패널이 34px 넘친다.** 관찰 → 다음 프레임 재배분 사이의
  지연이다. **이유:** 순간적이고 정착하면 0 이다.
- **Q-sphere 6큐비트 라벨은 77% 가 겹친다.** 라벨이 월드 크기 스프라이트라 지름을 키우면 라벨도
  같은 비율로 커져 **겹침 비율이 지름과 무관하다**(2부 실측, `style.css` 열 토큰 주석의 3열 최대). **이유:** 3열을
  넓혀서는 풀리지 않는다 — 라벨 배치를 바꾸는 일이라 백로그.
